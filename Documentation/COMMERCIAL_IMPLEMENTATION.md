기준 문서: `Cozy_Animal_Survivors_Commercial_GDD_v1.0.pptx` (2026-09-10, 52쪽).
본문과 발표자 노트의 추출본은 `COMMERCIAL_GDD_SOURCE.txt`.
게임 규칙 버전: `commercial-0.3.0`. 앱 버전: `0.3.4`. Unity: **6000.3.23f1**.
사용자 확정 플랫폼(2026-09-10): **Android 모바일**, 가로 화면·터치 드래그. 기획서와 플랫폼 설명이 다를 경우 이 확정을 우선한다.

## 실행

- `Assets/Cozy/Scenes/AuroraSnowfield.unity`를 열고 Play.
- 새 모험에서 동물·지역·난도를 선택한다. 펭귄과 카피바라, 눈밭이 처음부터 열린다.
- 눈밭을 완료하면 고양이·온천·눈밭 무한 도전, 온천을 완료하면 우체국이 열린다.
- WASD / 방향키 / 패드 왼쪽 스틱 / 화면 드래그로 이동한다. 자동 공격이다.
- 메뉴는 마우스·터치, 키보드 방향키/Enter, 패드 방향키/A로 조작한다. ESC/START는 일시정지.
- Unity 메뉴 `Cozy > 3. Validate commercial rules`로 시뮬레이션 회귀 검증.
- `Cozy > 2. Build Android APK`로 `Builds/Android/CozySurvivors-v0.3.4.apk` 생성. Android 8.0+, ARM64 IL2CPP, 개발용 서명, 버전 코드 7.
- 개발용 APK는 테스트 전체 해금이 기본 ON이다. v0.3.3 첫 실행에는 기존 OFF 설정도 ON으로 한 번 전환하고, 이후 변경한 설정은 유지한다. 설정 화면에서 OFF로 전환하면 실제 진행에 맞는 동물·지역·무한 모드·장식·편지 조건으로 돌아간다. 자세한 동작은 `TEST_MODE.md`를 참조한다.
- `Cozy > 4. Build commercial Windows demo`는 개발 검증용 보조 빌드다.

## 코드 구성

- `CozyRules.cs`: 규칙 버전, 동물·적·무기·지역 기본값.
- `CozyRun.cs`: 고정60Hz 전투/성장/목표/보스 시뮬레이션. 상태와 난수 생성기까지 직렬화한다.
- `CozySave.cs`: 체크섬, 원자적 교체, 백업 복원, 중복 정산 방지, 해금·장식·기록.
- `CozyGame.cs`: 기존 씬의 진입점. 입력, 고정 스텝 진행, 저장·화면 연결.
- `CozyGame.Menus.cs`: 타이틀, 선택, 성장, 결과, 마을, 설정.
- `CozyGame.World.cs` / `CozyGame.Drawing.cs`: 재사용하는 UI 렌더 객체, 판정 예고, 아이콘, 기존 펭귄 리소스·오디오.
- `CozyChecks.cs`: Unity에서 실행하는 시뮬레이션/저장 검증.
- `CozyGame.Validation.cs`: 개발 빌드의 화면 캡처와 실제 Input System 경로 검증.

새 전투의 수치는 `CozyRules`가 관리한다. 기존 씬의 `CozyFeel.asset` 참조는 호환성을 위해 유지되며 새 전투 수치를 바꾸지는 않는다. 밸런스를 바꾸면 `CozyRules.Version`을 함께 올려 기록을 분리한다.

## 저장

`Application.persistentDataPath/commercial-profile.json`과 `.bak` 한 개를 사용한다.
기존 `PlayerPrefs`의 `Cozy.Penguin.Best`는 수정하지 않고 도감에 legacy 기록으로 읽는다.

새 모험, 성장 선택, 유물 선택, 일시정지/포커스 해제, 결과 정산, 영구 설정 변경 시 저장한다. 실행 중인 모험에는 시드, RNG 상태, 적/공격/드롭, 쿨다운, 목표, 선택 큐를 저장한다. 일시정지에서 나가면 계속하기로 재개한다. 같은 runId는 한 번만 정산한다. 저장 실패 시 모험을 유지하고 화면에 알린다. 주 파일 손상 시 검증된 백업으로 복원하며 둘 다 손상되거나 호환되지 않으면 기존 파일을 덮어쓰지 않는다.

Unity가 null 모험을 기본값 객체로 직렬화하는 경우에는 정확히 기본값인 객체만 빈 모험으로 복원한다. 실제 모험의 잘못된 스냅샷은 계속 거부한다. `InvalidDataException`도 백업 복원 경로로 처리해 시작 화면이 중단되지 않으며, 자동 화면 검증은 시작부터 별도 프로필을 사용한다.

## 상용 출시 전에 남은 일

현재 결과물은 기획서에 따른 기능 검증용 개발 빌드다. 아래 항목까지 끝난 상용 출시판이라는 의미는 아니다.

- 카피바라 1번(유자 온천)·고양이 2번(삼색 편지지기)의 실제 8프레임 idle을 플레이와 선택 화면에 적용했다. 펭귄의 기존 행동 애니메이션은 유지한다. 두 추가 동물의 이동·피격·공격·퇴장 전용 동작은 아직 없어서 idle을 기본 표현으로 사용한다. 추가 지역·적·보스는 임시 시각 리소스이며, 나머지 기획 애니메이션과 적18외형, 음악5곡/효과음25종은 별도 제작 대상이다.
- 장식은 구매/영구 배치 상태와 간단한 표현까지, 도감 업적은 로컬 기록까지 구현한다. Android 플랫폼 업적·클라우드 저장·스토어 API는 아직 연결하지 않는다.
- 전문 현지화, 글씨 확대의 전체 해상도 검수, 패드 종류별 검수와 장치 분리, 실기기 성능/메모리 측정이 필요하다.
- 자동 검증의 승리 주입은 결과·해금 경로를 검사하는 것으로, 모든 조합의 실제 난도/완주 가능성을 증명하지 않는다. 무한 시뮬레이션도 60fps 실기기 성능 보장이 아니다.
- 신규 플레이어12명, 3시드×3전략×3회 관찰, 재미·난도 조정은 실제 플레이로 진행해야 한다.
- 상점 공개, 가격 설정, 계약·권리 확인, 행사 신청, 마케팅 집행은 이 로컬 개발 작업에 포함하지 않는다.
